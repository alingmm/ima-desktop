# 后端重大改造需求（去除云端凭证依赖 + 规避安装运行报错）

## 一、背景与根因（必读）

当前项目打包成 Windows exe 后，用户本地核心功能全部失效（对话无反应、搜不了网、生成不了视频、知识库无法向量化），且出现安装/运行报错。根因有两类：

**根因1（功能失效）：云端凭证只在沙箱存在**
1. server 端通过 coze-coding-dev-sdk 的 `new Config()` 无参构造自动获取 API Key，该凭证只在 Coze 沙箱运行时存在，用户本地不存在；
2. Supabase 客户端通过 `python3 coze_workload_identity` 动态拉取凭证，同样只在沙箱有效。

**根因2（安装/运行报错）：打包后代码只读 + 加载时序错误**
1. Electron 打包后代码被压缩进只读的 `app.asar`，后端若用 `path.resolve(__dirname, '../../uploads')` 等写法在 asar 内创建目录/写文件，必然报 `ENOTDIR, not a directory`；
2. `main.ts` 若在文件顶部 `require('../server/dist/index.js')`，会导致后端在环境变量赋值前就被加载，回退到只读目录再次报错。

改造目标：彻底移除 coze-coding-dev-sdk 和 Supabase 依赖，改为「本地配置文件 + OpenAI 兼容接口 + 本地文件存储」，所有动态写入都在系统可写目录内完成，使打包后的 exe 在用户本地无需任何沙箱凭证即可正常使用。

## 二、改造内容

### 【A. 本地配置管理】
- 新增配置模块，配置文件存于用户数据目录下 `config.json`。
- 用户数据目录（userData）：Electron 主进程通过 `app.getPath('userData')` 获取后，赋值给环境变量 `USER_DATA_PATH`，再传给后端；后端若未取到该环境变量，回退到 `os.homedir() + '/.ima-workstation'`。
- `config.json` 字段：`openaiBaseUrl`（默认 https://api.openai.com/v1）、`openaiApiKey`、`chatModel`（默认 gpt-4o-mini）、`embeddingModel`（默认 text-embedding-3-small）、`searchApiKey`（Tavily，默认空）、`searchProvider`（默认 tavily）。
- 提供 `GET /api/settings`（读取，apiKey 类字段脱敏：只返回是否已配置 + 尾4位）和 `POST /api/settings`（写入）接口。

### 【B. 数据层：Supabase → 本地 JSON 文件存储】
- 彻底移除 Supabase 依赖及 python3 workload identity 拉取逻辑。
- 改为本地 JSON 文件存储，存于 `{USER_DATA_PATH}/data/` 下。
- 覆盖实体：users、user_settings、conversations、messages、knowledge_bases、documents、document_chunks（含向量数组）、knowledge_shares、knowledge_collaborators、video_tasks、search_history、notes。
- 封装统一 storage 模块（增删改查），尽量保持现有 routes 层调用语义和返回字段不变，减少上层改动。
- 向量检索：文档分块存向量后，检索用内存余弦相似度实现（个人知识库规模，无需外部向量库）。

### 【C. AI 服务层：coze-coding-dev-sdk → OpenAI 兼容接口】
- 移除 coze-coding-dev-sdk 依赖。
- LLM 对话：用原生 fetch 调用 `${openaiBaseUrl}/chat/completions`，支持流式（SSE）返回和多轮对话，从 config.json 读取 openaiApiKey 和 chatModel。
- Embedding：调用 `${openaiBaseUrl}/embeddings`，从 config.json 读取 embeddingModel 和 openaiApiKey。
- 凭证从 config.json 读取，绝不依赖沙箱运行时注入。

### 【D. 联网搜索：接入 Tavily】
- 用原生 fetch 调用 `https://api.tavily.com/search`（POST，body 含 api_key、query），api_key 从 config.json 的 searchApiKey 读取。
- 保留原 `/api/search` 路由语义和返回结构尽量不变。

### 【E. 视频生成：保留框架】
- video 相关路由和前端页面全部保留；后端在未配置视频凭证时返回明确提示信息（如 `{ error: 'VIDEO_NOT_CONFIGURED', message: '请在设置中配置视频服务' }`），不调用已失效 SDK，也不报 500。

### 【F. 错误处理增强】
- 所有 /api 路由返回具体错误信息，不再只返回通用文案（如 'Stream error'）。
- 当 openaiApiKey / searchApiKey 未配置时，返回明确错误码和引导文案（如 `{ error: 'API_KEY_NOT_CONFIGURED', message: '请先在设置页填写 API Key' }`），便于前端识别并引导。

### 【G. 可写目录与加载时序（规避安装/运行报错）】
1. **动态文件全部写入 userData**：uploads 上传目录、data 数据目录、config.json 均基于 `process.env.USER_DATA_PATH` 构建，禁止任何 `path.resolve(__dirname, '../../uploads')` 之类写入 app.asar 的写法。
2. **后端延迟加载**：确认 `electron/main.ts` 中后端模块的 `require` 已移到 `app.whenReady()` 之后、且在 `process.env.USER_DATA_PATH = app.getPath('userData')` 赋值之后执行（放在 startBackend 函数内部），不要放在文件顶部。
3. 后端在启动时确保 `{USER_DATA_PATH}/uploads` 和 `{USER_DATA_PATH}/data` 目录存在（mkdir recursive）。

### 【H. 打包配置修复】
1. 检查 `tsconfig.electron.json`，若 `moduleResolution` 为 `"bundler"` 改为 `"node"`（Electron + commonjs 兼容）。
2. `package.json` 检查 JSON 语法（无重复键、无漏逗号），确保 `build` 字段与 `scripts` 字段层级正确；在 pnpm 下确认 electron/esbuild 在 `pnpm.onlyBuiltDependencies` 或 `allowBuilds` 白名单内，避免 `ERR_PNPM_IGNORED_BUILDS`。

## 三、验收标准
- 后端 tsc 编译通过，无类型错误。
- package.json 中移除 coze-coding-dev-sdk 和 Supabase 相关依赖。
- 现有前端调用的所有 /api 路由语义保持兼容（路径、方法、返回字段尽量不变）。
- 凭证缺失时返回明确错误码而非静默失败或 500。
- 代码中不存在任何写入 app.asar 只读目录的 `__dirname` 相对路径写法（uploads/data/config 均指向 USER_DATA_PATH）。
